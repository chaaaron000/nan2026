## Overview

현재 프로젝트는 ScriptableObject 기반 콘텐츠, 일반 C# 도메인 로직, MonoBehaviour 기반 화면·입력 계층, 씬 간 전역 서비스로 나뉜다. 플레이의 구성 루트는 `GridTestController`이며, 타이틀에서 고른 `StageData`를 받아 격자·정답·물감통·클리어 판정을 연결한다. 핵심 규칙은 `GridState`와 `PaintSpreadCalculator`에 있고, 화면 연출은 `GridView`, `CellView`, `PaintSpreadSequencePlayer`가 담당한다.

## 계층별 구성

| 계층 | 핵심 타입 | 책임 |
|---|---|---|
| 콘텐츠 | `StageData`, `StageCatalog`, `ColorPaletteSO`, `SoundLibrary` | 스테이지와 공통 리소스의 직렬화 |
| 도메인 | `GridState`, `PaintSpreadCalculator`, `PaintApplicationPlan`, `StageClearChecker` | 좌표·벽·색 상태, 확산 계획, 정답 판정 |
| 행동 | `ICommand`, `PaintBucketUseCommand`, `CommandController` | 물감 사용과 역순 복원 |
| 화면·입력 | `GridView`, `CellView`, `PaintBucketController`, UI 클래스 | 오브젝트 생성, 입력 중계, 상태 표현과 연출 |
| 앱 흐름 | `StageRunContext`, `SceneTransitionManager`, `GameSettingsService`, `SoundManager` | 씬 간 상태와 지속 서비스 |

도메인 객체는 Unity 생명주기를 상속하지 않아 규칙과 화면을 분리한다. 반면 좌표 타입은 `Vector2Int`, 시간은 Coroutine과 `Time.deltaTime`을 사용하므로 완전히 Unity 독립적인 어셈블리까지 분리된 상태는 아니다.

## 플레이 구성 루트

`GridTestController`는 현재 다음 객체를 조립한다.

1. 선택된 `StageData`로 플레이용 `GridState`와 읽기 전용 정답용 `GridState`를 만든다.
2. 두 `GridView`를 생성하고 정답판에 목표 `PaintState` 배열을 표시한다.
3. `StageClearChecker`와 `PaintBucketController`를 초기화한다.
4. 물감 사용 요청을 커맨드로 바꾸고 확산 연출을 시작한다.
5. 연출 종료 후 입력을 다시 열고 정답 일치를 검사한다.

클래스 이름에는 `Test`가 남아 있지만 Build Settings의 실제 플레이 씬인 `GridTestScene`에서 런타임 오케스트레이터로 쓰인다.

## 상태의 권위와 동기화

권위 있는 퍼즐 상태는 `GridState`다. `PaintBucketUseCommand.Execute`는 확산 계획의 모든 결과를 모델에 즉시 적용하며, `PaintSpreadSequencePlayer`는 같은 계획을 거리별로 재생해 View를 뒤따라 갱신한다. Undo는 계획에 저장된 `PreviousState`를 모델과 View 양쪽에 즉시 복원한다.

이 구조에서는 연출 중 모델이 이미 최종 상태이므로 입력 잠금이 핵심 불변식이다. `GridTestController`가 확산 시작부터 완료까지 `PaintBucketController`와 `CommandController`를 함께 비활성화해 중간 상태에 새 행동이 끼어들지 않게 한다.

## 콘텐츠 현황

`StageCatalog`에는 10개 실제 스테이지가 등록되어 있다. 타이틀의 미리보기와 플레이 씬은 같은 `StageData`를 읽으므로 제목, 설명, 크기, 벽, 정답, 물감통 구성이 단일 소스에서 유지된다. 커스텀 `StageDataEditor`는 인스펙터에서 벽과 정답 셀을 직접 편집하고 Unity Undo를 지원한다.

## 현재 확장 경계

- `StageCleared` 이후 진행 저장과 결과 UI는 아직 연결되지 않았다.
- Redo와 커맨드 실패 롤백은 없다.
- 설정 UI는 팝업 생명주기 중심이며 실제 설정 컨트롤 연결은 별도 작업이다.
- 전역 객체는 공통 제너릭 싱글톤과 `SoundManager` 자체 구현이 혼재한다.
