# 타이틀과 스테이지 선택 흐름

## Overview

타이틀 UI는 메인과 스테이지 선택 패널을 하나의 이동 루트 아래에 두고 DOTween으로 전환한다. 스테이지 선택은 3개의 미리보기 패널만 재사용하는 캐러셀이고, 선택 결과를 지속 컨텍스트에 저장한 뒤 준비 완료 신호를 지원하는 비동기 씬 전환으로 플레이를 시작한다.

## 타이틀 패널 전환

`TitleUIController`는 `PanelType`과 패널별 `CanvasGroup`, 목표 위치를 직렬화된 Dictionary로 관리한다. 전환 중에는 이전 패널 입력을 즉시 막고 루트를 대상 위치의 반대로 이동한다. 완료 후 이전 패널을 숨기고 대상 패널만 상호작용 가능하게 한다. 비활성화 후 다시 켜지면 Main 상태로 즉시 정규화한다.

`UITitleMainPanel`은 시작, 설정, 종료 버튼을 각각 패널 이동, `GameSettingsService.ShowSettings`, `Application.Quit`에 연결한다.

## 3슬롯 미리보기 캐러셀

`StagePreviewSystem`은 이전·현재·다음 위치에 패널 3개를 생성한다. 좌우 이동이 끝나면 화면 밖 패널 하나를 반대편으로 옮기고 새 `StageData`에 다시 Bind한다. 스테이지 수만큼 패널을 만들지 않으므로 콘텐츠가 늘어도 패널 인스턴스 수는 일정하다.

슬라이드 중에는 탐색 버튼과 현재 스테이지 조회를 막는다. 양 끝에서는 이동할 수 없는 방향 버튼을 비활성화한다. 비활성화로 Tween이 중단되면 3개 패널을 현재 인덱스 기준으로 다시 배치·바인딩한다.

## 미리보기 렌더링

`UIStagePreviewPanel`은 셀과 벽 오브젝트를 풀로 보유하고 필요한 수만 활성화한다. `GridIndexUtility`와 `GridLayoutUtility`를 재사용하므로 인게임 격자와 같은 좌표·배치 규칙을 따른다. 컨테이너 크기에 맞춰 셀 크기를 계산하고 정답 색, 벽, 제목, 설명을 표시한다.

팔레트나 심볼 표시 설정이 변경되면 활성 셀만 다시 그린다. 이는 스테이지 데이터의 논리 상태를 바꾸지 않고 표시만 교체한다.

## 씬 시작

시작 버튼은 중앙 스테이지를 얻어 `StageRunContext`에 저장하고 `GridTestScene` 로드를 요청한다. `SceneTransitionManager`는 화면을 덮은 뒤 씬을 비동기로 로드하고, 플레이 콘텐츠가 `NotifySceneReady`를 보낼 때까지 검은 화면을 유지한다. 중복 요청과 Build Settings에 없는 씬은 거절한다.
