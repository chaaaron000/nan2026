# 스테이지 데이터와 실행 흐름

> Sources: NaN2026 현재 코드베이스, 2026-08-02
> Raw: [NaN2026 Current Codebase Analysis Snapshot](../../raw/implementation/2026-08-02-current-codebase-analysis.md)
> Updated: 2026-08-02

## Overview

스테이지 콘텐츠는 `StageData` 에셋에 모이고 `StageCatalog`가 선택 화면의 순서를 정한다. 선택된 에셋은 `StageRunContext`가 씬 사이에서 보관하며, 플레이 씬의 `GridTestController`가 이를 모델·View·물감통·정답 판정기로 펼친다. 현재 카탈로그에는 10개 스테이지가 등록되어 있다.

## StageData

`StageData`는 다음 값을 직렬화한다.

- 격자 `Width`, `Height`
- 선택 화면과 인게임에 표시할 `Title`, `Description`
- 개별 물감통 사양 목록 `PaintBuckets`
- 2배 좌표계의 내부 벽 목록 `WallPositions`
- 행 우선 목표 색 배열 `AnswerPaintStates`

`OnValidate`는 크기를 1 이상으로 제한하고, 크기 변경 시 겹치는 좌표의 정답을 보존해 배열을 다시 만든다. 유효하지 않은 PaintState 비트는 Empty로 정규화하며, 범위 밖·중복·셀 중심·모서리 좌표인 벽을 제거한다.

## 제작 도구

`StageDataEditor`는 기본 필드 외에 벽 편집 격자와 정답 팔레트를 그린다. GUI의 아래쪽 증가 Y축을 게임 좌표와 맞추기 위해 행을 뒤집어 표시한다. 벽과 정답 변경 전에 `Undo.RecordObject`를 호출하므로 에셋 편집도 Ctrl+Z로 복원된다.

## 선택에서 플레이까지

```text
StageCatalog
  → StagePreviewSystem.TryGetCurrentStage
  → StageRunContext.SelectStage
  → SceneTransitionManager.LoadSceneAndWaitForReady
  → GridTestController.Start
  → CreateTestGrid
  → SceneTransitionManager.NotifySceneReady
```

`StageRunContext`는 `LazyPersistentSingleton<StageRunContext>`로 씬 전환 뒤에도 선택된 `StageData` 참조를 유지한다. 플레이 씬에 Inspector용 기본 `stageData`가 있어도 선택된 값이 있으면 이를 우선한다.

## 플레이 초기화

`CreateTestGrid`는 활성 확산 연출을 즉시 완결하고 커맨드 이력을 폐기한 뒤 새 상태를 만든다. 플레이판은 클릭 가능하게, 정답판은 클릭 불가능하게 생성한다. 두 판은 동일한 크기와 벽을 공유하고 정답판에만 `AnswerPaintStates`를 일괄 표시한다.

씬 전환은 단순 로드 완료만 기다리지 않는다. `GridTestController`가 격자와 물감통 생성을 마친 뒤 `NotifySceneReady`를 보내야 전환 화면이 열린다. StageData 누락으로 초기화에 실패해도 전환이 영구 대기하지 않도록 준비 신호를 보내고 컴포넌트를 비활성화한다.

## 클리어 판정

`StageClearChecker`는 플레이 격자의 모든 행 우선 셀을 정답 배열과 비교한다. 처음 일치했을 때만 `StageCleared` 이벤트를 발생시키고 이후 Check는 true만 반환한다. 판정은 확산 연출 완료 후 실행되므로 플레이어가 결과를 본 시점과 클리어 시점이 일치한다. 현재 이벤트 처리 결과는 로그 출력뿐이다.
