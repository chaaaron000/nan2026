# 물감통 사용 예약

> Sources: NaN2026 물감통 사용 예약 구현, 2026-08-04

## Overview

물감통 사용 예약은 현재 물감 확산 연출이 진행되는 동안에도 다음 물감통 드래그 입력을 미리 받기 위한 입력 흐름이다. 실제 `PaintBucketUseCommand` 실행은 한 번에 하나씩 직렬로 유지하고, 연출 중 들어온 요청은 `GridController`의 큐에 저장했다가 현재 연출이 끝나는 즉시 다음 커맨드로 실행한다. 예약된 물감통은 사용된 물감통처럼 즉시 숨겨 중복 입력과 레이아웃 되돌림을 막는다.

## 설계 목표

기존 구조에서는 물감통 하나를 사용하면 확산 연출이 끝날 때까지 `PaintBucketController`와 `CommandController` 입력을 모두 잠갔다. 이 방식은 모델 상태와 연출을 안전하게 유지하지만, 플레이어가 다음 수를 알고 있어도 연출이 끝날 때까지 기다려야 했다.

예약 기능의 목표는 입력 반응성을 높이면서도 기존 커맨드 불변식을 유지하는 것이다.

- 확산 연출 중 다음 물감통 드래그/드롭을 허용한다.
- 연출 중에는 Undo/Clear 같은 커맨드 UI는 계속 막는다.
- 다음 물감통 사용은 즉시 실행하지 않고 큐에 예약한다.
- 예약된 물감통은 추가 선택·드래그·예약을 받지 않는다.
- 마지막 예약까지 모두 실행된 뒤에만 정답 판정을 수행한다.

## 실행 흐름

```text
물감통 사용 요청
├─ activePlan 없음
│  └─ ExecuteBucketUse
│     ├─ PaintBucketUseCommand 실행
│     ├─ activePlan 저장
│     ├─ Command 입력 잠금
│     ├─ Bucket 입력 유지
│     └─ PaintSpreadSequencePlayer.Play 시작
└─ activePlan 있음
   └─ ReserveBucketUse
      ├─ PaintBucketController.Reserve
      ├─ pendingBucketUseRequests.Enqueue
      └─ 예약 피드백 재생

연출 완료
├─ activePlan 비움
├─ 입력 상태 복구
├─ 예약 큐가 있으면 다음 요청 실행
└─ 예약 큐가 없으면 StageClearChecker.Check
```

`activePlan`은 현재 재생 중인 확산 계획이 있다는 신호다. 이 값이 있으면 이미 하나의 커맨드가 모델 상태를 최종값으로 바꿨고, View가 그 계획을 뒤따라 재생하는 중이다. 따라서 같은 시점에 또 다른 커맨드를 실행하면 연출 기준과 Undo 스냅샷의 의미가 흐려질 수 있다.

## 예약 큐

`GridController`는 `Queue<PendingBucketUseRequest>`로 예약을 보관한다. 예약 항목에는 다음 값이 들어간다.

| 값 | 역할 |
|---|---|
| `BucketId` | 같은 사양의 물감통을 구분하는 런타임 ID |
| `Bucket` | 커맨드 생성에 필요한 색상과 범위 사양 |
| `GridPosition` | 플레이어가 드롭한 셀 좌표 |

예약은 FIFO로 실행된다. 플레이어가 연출 중 여러 물감통을 차례로 드롭하면 입력한 순서대로 다음 커맨드가 실행된다.

예약 큐에서 꺼낸 요청은 `ExecuteBucketUse(..., false)`로 실행한다. 예약 시점에 이미 사용 효과음을 재생했기 때문에 실제 실행 시점에는 같은 소리를 반복하지 않는다. 실행에 실패하면 `ReleaseReservation`으로 물감통 예약 상태를 되돌린다.

## 입력 잠금 분리

예약 기능의 핵심은 커맨드 입력과 물감통 입력을 분리한 점이다.

```text
SetGameplayInputEnabled(commandInputEnabled, bucketInputEnabled)
```

커맨드 실행 직후에는 `SetGameplayInputEnabled(false, true)`가 호출된다. Undo/Clear는 진행 중인 커맨드의 계획과 이력을 깨뜨릴 수 있으므로 막고, 물감통 컨트롤러는 다음 드래그/드롭을 받을 수 있게 둔다.

기존의 `SetGameplayInputEnabled(bool enabled)` 오버로드는 둘을 같은 값으로 설정하는 편의 함수로 남아 있다. 초기화나 강제 완료처럼 전체 입력을 함께 복구할 때 사용한다.

## 예약 상태

`PaintBucketController.BucketEntry`는 `IsConsumed`와 별도로 `IsReserved`를 가진다.

```text
BucketEntry
├─ IsConsumed: 커맨드 실행으로 실제 소모된 상태
└─ IsReserved: 아직 실행 전이지만 다음 사용으로 잡힌 상태
```

예약 상태는 소모 상태와 다르다. 아직 `PaintBucketUseCommand`가 실행되지 않았으므로 Undo 스택에 들어가지 않았고, 모델 상태도 바꾸지 않았다. 하지만 플레이어 관점에서는 이미 다음 사용으로 제출한 물감통이므로 다시 사용할 수 없어야 한다.

`Reserve`는 이미 소모되었거나 예약된 물감통을 거부한다. 예약 가능하면 선택을 해제하고 View에 예약 상태를 반영한다. 클릭, 선택 후 셀 클릭, 드래그 드롭 경로는 모두 `IsConsumed || IsReserved`이면 무시한다.

실제 커맨드가 실행되어 `Consume`이 호출되면 예약 상태를 해제하고 소모 상태로 확정한다. 초기화나 비활성화처럼 예약이 실제 실행되지 않고 폐기되는 경우에는 `ClearPendingBucketUseRequests`가 큐를 비우며 `ReleaseReservation`을 호출한다.

## 화면 표현

예약된 물감통은 반투명으로 남기지 않고 소모된 물감통처럼 숨긴다. 드래그 중에는 `LayoutElement.ignoreLayout`로 물감통 슬롯이 빠지고 아래 항목들이 올라오는데, 드롭 후 예약 물감통을 다시 보이게 하면 레이아웃이 되돌아오는 어색한 흔들림이 생긴다.

따라서 `PaintBucketView.RefreshAvailability`는 다음 조건으로 UI GameObject와 월드 비주얼을 활성화한다.

```text
!isConsumed && !isReserved
```

이 방식은 예약된 물감통을 “이미 제출된 다음 행동”으로 보여주며, 동시에 추가 클릭·드래그 입력도 막는다.

## 정답 판정

정답 판정은 현재 연출이 끝날 때마다 바로 수행하지 않는다. `HandlePaintSequenceCompleted`는 예약 큐에 다음 요청이 있는지 먼저 확인한다. 다음 예약이 실행되어 새 `activePlan`이 생기면 정답 판정을 건너뛰고 다음 연출을 기다린다.

예약 큐가 비어 있고 더 이상 시작된 연출이 없을 때만 `StageClearChecker.Check(gridState)`를 호출한다. 플레이어가 연속으로 여러 물감통을 예약한 경우 중간 상태로 클리어 판정이 나지 않게 하기 위한 순서다.

## 실패와 초기화 처리

예약된 요청이 실제 실행 시점에 실패할 수 있는 대표 이유는 물감통 상태가 이미 바뀌었거나 커맨드 입력이 예상과 다르게 막힌 경우다. 이때 큐 항목은 버리고 `PaintBucketController.ReleaseReservation`으로 View 상태를 되돌린다. 일반 플레이 흐름에서는 예약된 물감통이 다른 경로로 소모되지 않으므로 실패 가능성은 낮지만, 방어 코드는 예약 상태가 영구히 남는 문제를 막는다.

새 격자를 생성하거나 Controller가 비활성화될 때는 `CompleteActiveSequenceImmediately`로 현재 연출을 마무리하고 `ClearPendingBucketUseRequests`로 아직 실행되지 않은 예약을 모두 취소한다. 새 스테이지와 이전 예약이 섞이지 않게 하기 위한 생명주기 정리다.
